用 Go 写了一个 GitLab AI 代码审查工具（v0.3.0）

GitReviewAI 是一个用 Go 写的 GitLab AI 代码审查机器人。提交 MR 后自动触发审查，把 AI 生成的意见贴到评论区。支持自定义审查规则、多模型绑定、审计日志追踪，业务配置全部 Web 化管理。

📦 开源地址：https://github.com/yuhua2000/GitReviewAI

为什么要做这个？

团队用 GitLab 做代码评审，但有几个痛点：

  1. MR 经常没人看 — 人少事多，Review 经常被跳过
  2. 审查质量不稳定 — 不同人审查标准不一样，有的严格有的敷衍
  3. 明显问题被放过 — 空指针、SQL 注入、资源泄漏这种低级错误，人眼看多了也会漏

想了个办法：让 AI 先过一遍，把明显问题筛出来，人再重点看 AI 标记的地方。

不是替代人工审查，是帮人工审查提效。

它能干嘛？

核心流程

整个过程全自动，不需要人工干预。

具体功能

1. 行级评论 + 整体报告

AI 会针对具体代码行给出意见（比如”第 42 行有空指针风险”），也会生成一份整体审查报告。

2. 自定义审查规则

内置 11 条规则，按严重性分三级：

  • 🔴 ERROR — 逻辑错误、安全漏洞、并发问题、错误处理、数据一致性
  • 🟡 WARNING — 性能问题、代码规范、可维护性、代码格式
  • 🟢 INFO — 最佳实践、文档建议

每条规则可单独启用/禁用，也可以添加自定义规则。不同项目可以有不同的规则配置。

3. 多模型支持

不同项目可以用不同的 AI 模型：

支持注册多个模型，项目级绑定，全局默认兜底。

4. 审计日志

每次审查都记录一条日志：状态、模型、规则数、评论数、Token 消耗、耗时、失败原因。

Token 消耗能帮你估算成本，错误信息能快速定位问题。失败的审查可以一键重试。

5. 项目自动发现

不用手动注册项目。第一次收到某个项目的 MR Webhook 时，自动创建项目配置，用默认设置直接开始审查。事后在 Web 端调整即可。

6. 触发条件

  • 跳过 Draft MR
  • 指定目标分支（只审查合并到 main 的 MR）
  • 自动提交 or 人工审核后手动提交

技术实现

技术栈

  • 后端： Go 1.25 + Gin + SQLite
  • 前端： Vue 3 + Naive UI
  • AI： OpenAI 兼容 API（支持任意 OpenAI SDK 兼容的服务）
  • 部署： 单二进制 + Docker

架构设计

graph TD A[GitLab Webhook] --> B[Webhook Handler] B --> C[项目配置查询] C -->|首次| C1[自动建仓] C -->|已有| C2[读取配置] B --> D[触发条件检查] D -->|Draft/分支不匹配| D1[跳过] D -->|通过| E[AI 模型选择] E --> F[动态生成系统提示词] F --> G[AI 审查] G -->|Tool Call| G1[ReadFile] G -->|Tool Call| G2[FindInFile] G -->|Tool Call| G3[AddLineComment] G --> H[结果持久化 + 审计日志] H --> I[提交到 GitLab]

关键设计

动态系统提示词： 系统提示词不是固定的，而是根据项目启用的规则动态拼接。基础提示词 + 规则列表 + 自定义规则 + 项目专属要求。

Tool Calling： AI 通过调用工具来完成审查：ReadFile（读文件）、FindInFile（搜索代码）、AddLineComment（添加评论）、GenerateMDReport（生成报告）等。

对话压缩： 审查大 MR 时对话可能很长，超过阈值后自动压缩历史消息，保留关键信息。

Token 统计： 每次 API 调用都累加 Token 用量，记录到审计日志，方便成本核算。

实际使用场景

场景一：小团队提效

人少事多，MR 经常没人看。GitReviewAI 先过一遍，人工再重点看 AI 标记的地方。相当于多了一个 7x24 小时的初级审查员。

场景二：新手代码把关

实习生或新人提交的代码，AI 先扫一遍常见坑。带新人更省心，AI 帮你指出”这里应该检查 err”、”这里有空指针风险”。

场景三：安全扫描

启用安全相关规则（SQL 注入、XSS、权限绕过），AI 帮你做第一轮安全筛查。不替代专业安全工具，但能捞出一些明显问题。

场景四：代码规范统一

团队代码风格不一致？启用代码规范规则，AI 帮你检查命名、格式、magic number 等问题。配合自定义规则，可以强制团队规范。

为什么用 Go？

  1. 单二进制部署 — 编译完一个文件，拷到服务器就能跑
  2. 并发友好 — 多个 MR 同时审查，goroutine 天然支持
  3. 标准库够用 — HTTP、JSON、加密、数据库，标准库全有
  4. Docker 镜像小 — CGO disabled 后镜像很小

和其他方案对比

方案 特点 局限
GitLab 自带 免费，集成好 AI 功能弱，规则不灵活
SonarQube 功能强大 部署重，配置复杂
GitHub Copilot 体验好 不支持 GitLab
GitReviewAI 轻量、自托管、可定制 功能相对简单

GitReviewAI 的定位是：轻量级、自托管、可定制的 AI 代码审查工具。 不追求大而全，追求好用、省时间。

后续计划

  • 审查结果统计面板（按项目、按时间、按严重性）
  • 支持 GitHub（目前只支持 GitLab）
  • 审查结果 Webhook 回调通知
  • 更多 AI 模型适配（本地模型支持）

最后

这个项目的目标很明确：用 AI 帮团队做第一轮代码审查，把明显问题筛出来，人再重点看。

不替代人工审查，但能让人工审查更高效。
